# AGENTS.md

Operating instructions for AI coding agents working in this repo. `README.md`
orients a human toward the *claim*; this file orients an agent toward the
*discipline*.

> **This file contains only durable rules.** No dates, no status, no "in flight",
> no findings, no deadlines. Anything with a timestamp goes in `docs/journal/`.
> `just check` fails the build if any path named here stops existing.

## Bootstrap

```
uv sync          # the only command that assumes anything about the machine
just --list      # everything the repo can do
just verify      # lint + test + smoke + check. Run before committing.
just verify-full # verify + figures + paper. What CI runs; needs --group paper.
```

`just` is installed by `uv sync` as a locked dependency, so there is nothing else
to install on macOS, Linux or Windows. Every recipe body is a single
`uv run python ...` line; put real logic in Python, never in shell.

## Layout

| Path | What lives there |
|---|---|
| `src/lab/core/` | Plumbing: `paths.py`, `seeds.py`, `manifest.py`, `records.py`, `env.py`, `backend.py`, `provenance.py`, `checkpoint.py` |
| `src/lab/analysis/` | `stats.py` (intervals and tests), `integrity.py` (data validation) |
| `src/lab/check.py` | The linter that keeps this file and `CLAIMS.md` honest |
| `src/lab/size.py` | Repository size guard: no oversized blob reaches history |
| `src/lab/figstyle.py` | The house figure style. Every figure goes through it. |
| `experiments/` | One directory per experiment |
| `experiments/_template/` | Skeleton to copy for a new experiment |
| `experiments/e00_smoke/` | Permanent fixture and worked example. Do not repurpose. |
| `explore/` | Disposable exploration. Notebooks gitignored; `explore/FINDINGS.md` committed. Never cited by `CLAIMS.md`. |
| `figures/` | Committed figures, PDF and PNG, regenerated by `just figures` |
| `writeup/` | Paper source. The source is committed, the PDF is a build artifact. |
| `docs/journal/` | Dated working notes. All volatile state belongs here. |
| `CLAIMS.md` | The claim ledger: every number bound to the code that produced it |
| `scripts/` | Repo tasks invoked by the justfile |

Each experiment directory holds `spec.md`, `run.py`, `analyze.py`, `RESULTS.md`
and an `output/` directory. Records are written one shard per arm
(`records_<arm>.jsonl`) and read back with `paths.record_files()` — expensive runs
are rarely one process, and hand-merging shards is where duplicated and dropped
records come from. The package is permanently named `lab` and is never
renamed per project, so `from lab.core import ...` means the same thing in every
repo built from this scaffold.

## Decision rights

Most wasted time is not a wrong decision. It is a decision made by the wrong
party — an agent asking permission for something obvious, or proceeding on
something that needed a human. Sort every choice into one of three buckets.

**Decide yourself. Do not ask.**

- Naming, and file placement within the conventions above.
- Refactors that leave behaviour identical.
- Which statistic to use, when the spec already names one.
- Adding tests. Fixing a bug you found. Improving an error message.
- Anything reversible by `git checkout` that touches no data and costs nothing.

**Ask first. Stop and wait.**

- Spending money. Show the arithmetic: cost per call × number of calls.
- Anything that changes *what is being measured* — arms, stimuli, unit of
  analysis, sample size. That is a spec change, and the spec is the human's.
- Deleting or overwriting recorded data, including reruns that would replace an
  existing `output/`.
- Changing a spec after data exists against it.
- Any git operation: commit, branch, push.
- Adding a dependency.

**Proceed, but surface immediately. Do not bury it in a summary.**

- A result that contradicts an earlier one. Say so the moment you see it.
- A run that failed in a way suggesting the *design* is wrong, not the code.
- Any point where you are about to exceed the review checkpoint below.

**Review checkpoint.** Stop and show your work before creating or substantially
rewriting more than **five files** in one stretch. Ten small correct files built
on one wrong assumption are worth less than one file checked early.

## Method rules

These are not style preferences. Violating one invalidates a result.

1. **No control arm, no claim.** Anything the baseline also does is not an effect.
2. **n > 1.** One observation is an anecdote. Size for a tolerable interval width,
   not a round number.
3. **Vary exactly one factor.** A comparison that moves two things at once proves
   nothing about either.
4. **Seed everything and record the seed.** Use `seed_all()` at the top of
   `run.py`. Use `spawn()` for per-cell streams, never `seed + i`.
5. **Integrity-check before computing.** Call `check_records()` at the top of every
   `analyze.py`, pass `manifest=`, and `.raise_if_failed()`. A statistic on broken
   data is worse than no statistic, because it looks like a result.
6. **Build the synthetic path first, always.** Every experiment declares a backend
   and `stub` is the default. The stub costs nothing and catches analysis bugs in
   seconds; discovering them after a GPU bill is a choice, not bad luck.
7. **Stamp provenance at the point of measurement.** Every record carries
   `backend`, `model_id` and `dtype` via `backend.stamp()`. Provenance asserted by
   the writer is a comment; provenance derived from the artifact is a fact. Only
   the stamp survives an execution path that bypasses `run.py` — a remote
   launcher, a resumed job — and that bypass is not hypothetical: it has already
   caused real model output to be labelled synthetic.
8. **Never report a number from a non-reportable backend.** Stub and
   reduced-precision runs produce leads. Every report states which it is showing.
9. **Every rate gets an interval.** `wilson_ci` for proportions. A bare point
   estimate is not reportable. Overlapping intervals are not an effect.
10. **Include a comparison that should come out null.** If it fires, the method is
   broken, not the world.
11. **Never hand-author a number.** Every figure in `RESULTS.md` is written by
   `analyze.py`. Regenerate; do not edit. Generated files say so at the top.
12. **A negative result is a result.** Write the `RESULTS.md`, mark it NULL, commit
   it. Do not delete the experiment.
13. **Record retractions, do not erase them.** When a finding is withdrawn, add the
    retraction to `CLAIMS.md` and the journal. The history is the evidence that
    you checked.
14. **Explore in `explore/`, claim from `experiments/`.** The exploration stage
    wants a persistent kernel and no bookkeeping; a reportable number wants a
    committed script. Keep them in separate places rather than trying to make one
    artifact do both. `just check` fails if `CLAIMS.md` cites `explore/`, so the
    boundary is enforced rather than remembered.

## Writing a new experiment

1. `just check` to confirm the repo is clean.
2. Copy `experiments/_template/` to a new `experiments/e<NN>_<slug>/`. Numbering is
   sequential and never reused, so cross-references stay stable forever.
3. Write `spec.md` **before** any code — the question, the arms, the sample size,
   and what result would falsify the hypothesis.
4. Implement `run.py` (produces records, computes nothing) and `analyze.py`
   (consumes records, computes everything).
5. `just verify`, then add a row to `CLAIMS.md` **with a JSON pointer** —
   `path/to/summary.json#dotted.key` <!-- check:ignore --> — so the quoted number
   is checked against the artifact, not merely accompanied by it.

## Long-running and remote work

Anything that takes more than a few minutes, or runs somewhere other than this
machine, follows these. Each one exists because ignoring it has already cost a
diagnosis.

### Working in a notebook

The optional Jupyter setup, local and remote arrangements, agent access, and
clean shutdown instructions live in `explore/README.md`. Preserve a live kernel
unless the user asks to restart it; restarting discards in-memory state.

1. **Deploy, spawn, and checkpoint before the first real run.** Not after the
   first failure. Use `Checkpoint` from the start, so the answer to "it died at
   70%" is rerunning the command rather than reasoning about what survived.
2. **Own a long job in the foreground.** Poll it to completion yourself. Do not
   launch it, report success, and move on — a launch is not a result.
3. **Never `--detach` something whose output you need.** You lose the exit status
   and the failure mode, and you find out much later that you have no data.
4. **Never pipe a long-running command through `grep`, `tail` or `head`.** A
   shell pipeline reports the exit status of the *last* command, so a job that
   crashed exits 0 and the failure reads as success. Write the full output to a
   log, let the command's own status stand, then inspect the log. If you must
   pipe, `set -o pipefail` first — but writing a log is better, because you keep
   the part you did not think to grep for.
5. **A remote job needs a local record.** Its identifier, where its output lands,
   and how to check on it belong in the run log at launch time, not in your
   memory of the terminal.

Provider clients — Modal, Kaggle, SLURM, an inference API — belong in the project,
not in `src/lab/`. The scaffold deliberately ships none: they disagree about
everything, and a wrong abstraction here rots faster than the code it wraps.

## Hard constraints

- **Never commit `.env`, raw records, or model weights.** `.gitignore` covers
  these; do not add exceptions.
- **Never hand-transcribe model output into a document.** Generate evidence
  excerpts from the records with a script. Hand-transcription introduces
  fabricated text, and you will not notice.
- **Ask before spending money.** Show the arithmetic — cost per call times number
  of calls — before running anything metered.
- **Read primary sources before designing against them.** A fetched summary of a
  paper or a repo is a *hypothesis about* that source, not the source. Design
  decisions that rest on one are provisional until you have read the original —
  say so when you report them.
- **Do not commit unless asked.** Report what changed and let the human decide.
